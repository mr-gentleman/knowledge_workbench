## Decisions made (don't relitigate)
- **Candidate vs canon** only for metric identity. PIs (`metric_calc`) are never candidates; they attach to a
  candidate (`metric_id` NULL) then move to canon at promotion. No reassignment in V1.
- Candidate `status`: `open | promoted | rejected`. Duplicate of existing canon → reject +
  `duplicate_of_metric_id`, edit the canon instead. "Not ready" (no description / SQL fails) is a computed
  checklist, never a stored status.
- Canon / PI / fact table `status`: `active | retired`; the *why* goes in `revision.change_note`;
  optional `superseded_by` = "see instead" pointer.
- Promotion needs: description + ≥1 PI that passed its SQL check. Canon is edited directly afterward.
- Broken SQL edit on a live PI: save succeeds; Oracle keeps the last passing revision (`served_revision_no`).
  Running a check updates validation fields in place, not a new revision.
- Only `full_name` (no short_name). `disambig` = "when to use / how it differs" (metrics, PIs, fact tables).
  Synonyms → separate table later. `department` enum on candidate + core.
- `fact_table_core` keyed on `table_name_full` (AC.SCHEMA.TABLE) — no synthetic id (Snowflake TABLE_ID changes
  on CREATE OR REPLACE). Joins/dimensions/machine columns (`on_table_fields` etc.) deliberately excluded.
- `revision.record_id` is VARCHAR (numeric ids as text, or table names).
- Metric ids start at 100000 (legacy 2–90412). Schema disposable until first real import; then never reset.
- No served view in WORKBENCH — consumable dictionaries live in `DICTIONARY`; whatever builds them reads PIs at
  `served_revision_no`. See `docs/open-items.md` (legacy ID translation, schema placement).
- Viewer identity from `st.user`, never `CURRENT_USER()` (container runtime may return the service user).
