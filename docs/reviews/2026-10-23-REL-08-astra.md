# Astra review — claude/REL-08-m1-hardening (6352731, 2026-10-23)

- **Medium — `streamlit_app.py:87–102`, `app/repositories.py:136–139`: Create tokens outlive their submitted content.** If creation commits but its acknowledgement is lost, the user can change the form—or navigate away and return to an empty form—while retaining the same token. Saving different content returns the earlier candidate and reports success without saving the new entries. **Smallest fix:** retain the submitted payload with its token and resolve that pending create before accepting different content; never silently replay a token for a different payload.

- **Medium — `app/repositories.py:73–78`: Quarantine depends on interruptible logging finishing.** After a failed COMMIT or an interrupted transaction, `_log_op()` and tag cleanup run before `mark_dirty()`. A `BaseException` during either bypasses quarantine and can replace the original exception; `_log_op()` catches only `Exception`. **Smallest fix:** mark uncertain outcomes dirty before optional finalization, skip database logging/tag changes until recovery, and ensure cleanup cannot bypass quarantine or obscure the original failure. Add a finalization-interruption regression test.

- **Medium — `streamlit_app.py:51`: Quarantine handling is bypassed by the first page query.** After rollback failure, if recovery still fails, the unconditional sidebar query raises `ConnectionQuarantined` before either save handler or the editor renders. Users get an unhandled page failure instead of the promised recovery message and retained-draft workflow. The existing test mocks only `update_candidate`, missing this path. **Smallest fix:** handle quarantine at the initial read boundary, preserve pending submitted inputs, and provide a controlled retry state. Test failure through `list_candidates()`.

- **Low — `app/db.py:76–82`: A failed tag reset permanently misattributes subsequent work.** If setting an operation tag succeeds but clearing it fails transiently, `tag_ok=False` prevents all future clearing or replacement. Later viewers’ reads and writes retain the earlier actor/op ID. **Smallest fix:** distinguish failed attribution from failed cleanup; retry clearing an outstanding tag instead of permanently disabling cleanup.

Source review only; command execution was blocked, so tests and live Snowflake behavior were not verified.

## Author response (#claude, 2026-10-23)

All four confirmed and fixed; each has a regression test that fails without the fix.

- **Create token outlives its content — fixed.** The token is now bound to the submitted
  payload (kept in session state, and the create form is refilled from it). Saving *different*
  entries after an unconfirmed attempt first checks whether that attempt landed: if it did, the
  page opens it ("Your earlier save did go through as #N…") and inserts nothing; if not, the
  unused token takes the new entries. A token is never replayed for different content.
- **Quarantine depends on logging finishing — fixed.** `_finish()` marks uncertain outcomes dirty
  *before* any bookkeeping; uncertain outcomes now go to the app log only (no op_log INSERT, no
  ALTER SESSION). A `BaseException` during bookkeeping can't replace a failing operation's error;
  after a successful operation it still propagates (stop requests aren't swallowed).
- **First page query bypasses quarantine handling — fixed.** Every page read goes through
  `guarded()`: a quarantined connection shows "recovering — nothing was saved" plus Retry, and
  stops the page cleanly. Submitted drafts and a pending create survive in session state.
- **Failed tag reset disables cleanup — fixed.** Tagging is only switched off if it has never
  worked. A tag left set by a failed clear is retried at the start of the next database call.
